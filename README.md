# Active Metadata Management — 포털 데모

**데이터를 하나 올리면, 함께 쓸 수 있는 데이터가 따라온다.**

병원이 암환자 임상 데이터의 메타데이터를 올리면 국가 암 통계 중 무엇과 비교할 수 있는지, 방송사가 드라마 데이터를 올리면 어떤 시청률·화제성 지표를 붙일 수 있는지 — 지금은 담당자가 공공데이터포털을 검색하며 일일이 찾아야 합니다.
이 데모는 그 일을 **데이터셋 간 관계를 자동 판정해 두는 것**으로 푸는 포털의 화면입니다. 실제 운영 화면의 구성을 그대로 옮겼고, 데이터는 목업입니다.

**Live Demo**: https://syoooooung.github.io/3rd-party-active-metadata-demo/

---

## 데모에서 볼 수 있는 것

들어가면 **둘러보기**가 자동으로 시작해 6단계로 화면을 짚어 줍니다. 헤더의 `둘러보기` 버튼으로 다시 볼 수 있고, 건너뛰고 직접 돌아다녀도 됩니다.

| 화면 | 무엇을 보여주나 |
|---|---|
| **홈** | 통합 검색, 등록 현황, 디지털 집현전 7대분류 타일 |
| **데이터 찾기** | 분야·중분류·구분(외부 개방/기관 보유)·제공기관으로 거르는 검색. 결과 카드에서 **연계 데이터를 그 자리에서 펼쳐** 방사형 관계 지도로 봅니다 |
| **데이터 상세** | 함께 쓸 수 있는 데이터를 **관계 유형 4종으로 묶어** 제시 — 각 건에 결합 키·판정 신뢰도·하위라벨. 판정 전 데이터는 **관계 생성 실행**으로 그 자리에서 판정하고, 확신도 0.6~0.85 구간은 검토 대기로 남습니다 |
| **관계 지도** | 상세의 지도 보기. **직접 붙지 않는 데이터는 무엇(코드·기준표)을 거치면 붙는지 경로로** 제시하고, 색 구분이 어려운 경우를 위한 표 보기를 함께 둡니다 |
| **관리** | 수집 → 매핑 → 검토 대기 → 등재 파이프라인과, 자동 확정 기준(유사도 0.90) 미달 건을 사람이 처리하는 등재 검토 |

### 관계 유형 — 데이터셋 단위 4종

"이 데이터셋 옆에 왜 이걸 같이 보여주는가"에 하나씩 대응합니다. 유형이 다르면 화면에서 놓이는 자리도 다릅니다.

| 유형 | 묶음 이름 | 한 줄로 |
|---|---|---|
| `DETAIL_FOR` | 속성 보완 | 같은 대상인데, 여기에 없는 항목을 채워준다 |
| `STATISTIC_FOR` | 집계 맥락 | 값이 큰 건지 작은 건지 판단할 기준을 준다 — 분모 또는 비교 기준 |
| `ADJACENT_TO` | 인접 맥락 | 같은 맥락의 다른 대상이다 — 대안·다음 단계·관련 주제 |
| `SAME_KIND` | 동종 판본 | 같은 것의 다른 판본이다 — 지역·기관·규격·채널 |

파일·컬럼 단위로는 `VERSION_OF`(시점별 파일) · `COLUMN_MATCH`(같은 속성 컬럼) · `JOIN_KEY`(결합 키, 변환표를 거치는 경우 bridge)가 판정 근거로 붙습니다.

### 이 데모가 설명하려는 것

- **기관 보유 데이터와 외부 개방 데이터를 한 카탈로그에서** — 원본이 아니라 메타데이터를 올리고, 거기서 연계 가능한 공공데이터를 찾는다
- **관계는 유형과 근거로 제시한다** — 묶음 이름·결합 키·신뢰도·활용 설명이 함께 간다. 의미만 비슷하고 근거가 부족하면 "관계 미확정"으로 남긴다
- **확신이 부족한 판정은 자동 확정하지 않는다** — 데이터셋 간 관계는 확신도 0.6~0.85 구간, 메타데이터 매핑은 유사도 0.90 미만이 사람의 검토 대상이다
- **직접 붙지 않는 데이터를 어떻게 잇는가** — 암종 표기가 다른 국가 통계는 KCD 질병분류 코드를 거치면 붙는다. 목록으로는 표현할 수 없어 그래프가 필요하다
- **판정과 결합을 나눈다** — 포털의 산출물은 결합 키·값 정규화 필요 여부·미결합 예상까지의 판정과 근거이고, 실제 결합 실행은 그 판정을 받는 쪽의 몫이다

> 화면 데모입니다. 화면 구성과 관계 유형·임계값·판정 흐름은 실제 시스템과 같고,
> 데이터셋 이름과 건수는 실제 카탈로그를 본뜬 목업입니다.

## 실제 시스템은 어떻게 동작하나

```
[수집]  Airflow ETL — 공공데이터포털·KOSIS·보건의료빅데이터 등 이기종 소스의
        메타데이터(Schema.org / DCAT / SDMX / JSON-LD)를 수집해 원본 그대로 보존
   ↓
[통합]  DCAT 3.0 기반 통합 카탈로그 — 원본은 불변 스냅샷으로 보존,
        자동 매핑 결과는 Draft로 만들어 검토·승인 후 게시, 전 과정 계보(lineage) 추적
   ↓
[관계 생성]  의미가 가까운 후보를 임베딩으로 추리고, 컬럼 매칭(Transformer 임베딩 +
        XGBoost 타입 분류)과 LLM 판정을 거쳐 관계 유형 4종으로 저장 — 확신도 0.85
        이상은 확정, 0.6~0.85 구간은 검토 대기로 남겨 관계 판정 API로 승인·반려
   ↓
[제공]  포털 화면과 기관 시스템 연동 API(GET /explore/datasets/{name}/linkable)로
        판정 결과(관계 유형·결합 키·신뢰도·활용 설명)를 전달
```

**설계에서 정한 것들** (데모 화면에 그대로 반영돼 있습니다)

- **관계 유형은 데이터셋 단위 4종 + 파일·컬럼 단위 3종.** 공공데이터 목록개방현황 전수 조사와 실파일 파일럿으로 정했고, 유형마다 하위라벨을 분리해 저장한다
- **유사도 판정은 9단계 등급.** 완전 동일 1.00부터 하위·유사 항목 0.50까지. 자동 확정 기준은 0.90 — 0.70~0.90 구간을 시험해 정확도 저하 없이 과탐만 줄어드는 값으로 정했다
- **매핑 근거는 3계층으로 기록.** 후보 목록 · 알고리즘 추천 · 최종 결정을 분리해 저장한다. 추천 목록에 없는 값을 결정하면 별도 표기한다
- **식별자는 무손실 보존.** 데이터셋의 60%만 자체 식별자를 갖고 그중 50%만 URI 형태라, 주 식별자 하나로는 동일 데이터셋을 판별할 수 없다. 수집 과정에서 붙은 식별자를 모두 보존해 병합 판정에 쓴다
- 유사 속성 탐지 성능: 공개 벤치마크 12종 기준 **F1 평균 0.87** (baseline 0.72 → 0.94까지 개선된 데이터셋도 있음)

**스택** — FastAPI · PostgreSQL(JSONB) · DCAT 3.0 · Apache Airflow · MinIO · XGBoost · Transformers · LangGraph · React

## 실행

```bash
npm install
npm run dev
```

이 데모는 React + TypeScript + Vite로 만들었고, 외부 런타임 의존성은 React뿐입니다.
방사형·고리형 관계 지도는 라이브러리 없이 SVG로 직접 그렸습니다 — 노드 위치를 각도와 단계 수로 계산해 **항상 같은 배치**가 나오도록 했습니다.
온보딩 투어도 투어 라이브러리 없이, 대상 요소에 큰 `box-shadow`를 줘서 주변만 어둡게 하는 방식으로 만들었습니다 (오버레이 DOM이 없어 하이라이트된 요소를 그대로 클릭할 수 있습니다).

```
src/
  App.tsx          화면 셸 — 헤더, 메뉴, 화면 전환, 둘러보기 연동
  Tour.tsx         온보딩 투어 6단계
  data.ts          목 데이터 — 데이터셋·관계·분류 체계
  parts.tsx        결과 카드, 방사형 관계 지도, 관계 묶음
  amm.css          포털 화면 스타일 (실제 운영 화면에서 이식)
  portal.css       관리 화면·투어·고리형 지도 스타일
  screens/         홈 · 데이터 찾기 · 상세 · 고리형 지도 · 관리 2종
```
