# Active Metadata Graph — 포털 데모

**"어린이집이 인구 대비 충분한가"를 알려면 공공데이터포털에서 시설 목록을, 통계청에서 인구를 받아 엑셀에서 지역 이름을 맞춰야 합니다. 이걸 클릭 한 번으로 만들면 어떨까?**

공공데이터포털에는 어린이집 데이터가 196건 있습니다. 그중 103건은 **지자체마다 따로 올린 같은 형식의 자료**이고, 전국을 취합해 둔 통합본이 따로 있습니다. 사용자는 그걸 모른 채 목록을 훑습니다.
통계청 인구와 붙이려면 지역 표기가 `성남시`와 `경기도 성남시`로 달라 손으로 맞춰야 합니다.
2024년 공공데이터 활용기업 실태조사에서 **15.8%가 "공공데이터 간 결합·연계 활용이 원활하지 않다"** 를 애로로 꼽았습니다.

이 데모는 그 문제를 **데이터셋 간 관계를 미리 만들어 두는 것**으로 푸는 시스템의 화면입니다.
메타데이터를 표준 카탈로그로 통합하고, 데이터셋 사이의 관계를 자동 생성해, 사용자가 "무엇을 어떻게 붙일 수 있는지"를 찾아 헤매지 않게 합니다.

**Live Demo**: https://syoooooung.github.io/3rd-party-active-metadata-demo/

## 데모에서 볼 수 있는 것

들어가면 **둘러보기**가 자동으로 시작해 7단계로 화면을 짚어 줍니다. 헤더의 `둘러보기` 버튼으로 다시 볼 수 있고, 건너뛰고 직접 돌아다녀도 됩니다. 사용자 화면 3개와 운영 화면 2개입니다.

### 사용자 화면 — 찾고, 무엇이 붙는지 판정받는다

| 화면 | 무엇을 보여주나 |
|---|---|
| **1. 검색 결과** | 196건을 나열하지 않는다. 전국 통합본을 먼저 제시하고, 같은 형식의 지자체 자료 103건은 **동종 판본 하나로 접어** 보여준다 |
| **2. 데이터 상세** | 데이터 미리보기와 함께 "함께 쓸 수 있는 데이터"를 **관계 유형 4종으로 묶어** 제시. 각 건에 결합 키·판정 신뢰도·하위라벨을 근거로 붙이고, 의미만 비슷한 미확정 후보는 따로 접는다 |
| **3. 관계 지도** | 기준 데이터셋에서 이어지는 관계를 그래프로. **직접 붙지 않는 데이터는 무엇을 거치면 붙는지 경로로** 제시하고, 색 구분이 어려운 경우를 위해 표 보기를 함께 둔다 |

이 포털의 산출물은 **결합 가능 여부의 판정과 근거**까지입니다 — 결합 키, `성남시 ↔ 경기도 성남시` 같은 값 정규화 필요 여부, 미결합 예상 건을 전달하고, 실제 결합 실행과 지표 계산은 그 판정을 받은 결합 기능이 수행합니다. 화면 2 하단에 이 경계를 그대로 적어 두었습니다.

### 관계 유형 — 데이터셋 단위 4종

"이 데이터셋 옆에 왜 이걸 같이 보여주는가"에 하나씩 대응합니다. 유형이 다르면 화면에서 놓이는 자리도 다릅니다.

| 유형 | 묶음 이름 | 한 줄로 | 하위라벨 예 |
|---|---|---|---|
| `DETAIL_FOR` | 속성 보완 | 같은 대상인데, 여기에 없는 항목을 채워준다 | 이미 결합됨 |
| `STATISTIC_FOR` | 집계 맥락 | 값이 큰 건지 작은 건지 판단할 기준을 준다 | 분모 · 비교 기준 |
| `ADJACENT_TO` | 인접 맥락 | 같은 맥락의 다른 대상이다 | 대안 · 다음 단계 · 관련 주제 |
| `SAME_KIND` | 동종 판본 | 같은 것의 다른 판본이다 — 취합본이 있으면 접는다 | 지역 · 제공 채널 · 하위 유형 |

파일·컬럼 단위로는 `VERSION_OF`(시점별 파일) · `COLUMN_MATCH`(같은 속성 컬럼) · `JOIN_KEY`(결합 키, 변환표를 거치는 경우 bridge)가 판정 근거로 붙습니다. "함께 받은 것(co-usage)"은 유형에서 뺐습니다 — 활용 이력으로 학습하면 동종 판본만 나와서입니다.

### 운영 화면 — 수집한 메타데이터를 표준 카탈로그에 올린다

| 화면 | 무엇을 보여주나 |
|---|---|
| **4. 수집 현황** | 수집 → 매핑 → 검토 대기 → 등재 단계별 현황, 자동 확정률, 실행 이력 |
| **5. 등재 검토** | 자동 확정 기준(유사도 0.90) 미달 건. **원본 항목의 실제 값과 함께** 후보를 제시하고, 기존 카탈로그 항목과 중복인지 판정. 처리는 반려 · 보류 · 병합 등재 |

### 이 데모가 설명하려는 것

- **검색 결과를 관계로 묶으면 무엇이 달라지는가** — 103건을 훑는 대신 통합본 1건으로 끝난다
- **직접 붙지 않는 데이터를 어떻게 잇는가** — 법정동 코드를 거치면 통계청 자료와 붙는다. 목록으로는 표현할 수 없어 그래프가 필요하다
- **관계를 어디까지 판정하고 어디서 멈추는가** — 결합 키·정규화 필요 여부·미결합 예상까지 판정해 전달하고, 결합 실행은 하지 않는다
- **자동 판정을 사람이 어떻게 검토하는가** — 후보·추천·결정을 분리해 기록하고, 확신이 부족한 것만 사람에게 올린다. 메타데이터 매핑은 유사도 0.90 미만, 데이터셋 간 관계는 확신도 0.6~0.85 구간이 검토 대상이다

> 화면 데모입니다. 데이터는 목이지만 **실제 공공데이터포털·국가통계포털의 데이터셋 이름과 건수**를 씁니다.
> 관계 유형 4종과 묶음 이름, 임계값도 실제 설계·구현값입니다.

## 실제 시스템은 어떻게 동작하나

세 개의 서비스가 파이프라인을 이룹니다.

```
[수집]  Airflow ETL — 공공데이터포털·KOSIS·의료기관정보·영화DB 등
        이기종 소스의 메타데이터(Schema.org / DCAT / SDMX / JSON-LD)를 수집해 원본 그대로 보존
   ↓
[통합]  DCAT 3.0 기반 통합 카탈로그 — 원본은 불변 스냅샷으로 보존,
        자동 매핑 결과는 Draft로 만들어 검토·승인 후 게시, 전 과정 계보(lineage) 추적
   ↓
[관계 생성]  의미가 가까운 후보를 임베딩으로 추리고, 컬럼 매칭(Transformer 임베딩 + XGBoost
        타입 분류)과 LLM 판정을 거쳐 관계 유형 4종으로 저장 — 확신도 0.85 이상은 확정,
        0.6~0.85 구간은 검토 대기로 남겨 관계 판정 API로 승인·반려
        값 표기 정규화는 별도로 — "성남시 / 경기도 성남시"를 한 개체로 묶음
```

**설계에서 정한 것들** (데모 화면에 그대로 반영돼 있습니다)

- **관계 유형은 데이터셋 단위 4종 + 파일·컬럼 단위 3종.** 목록개방현황 전수 조사와 실파일 파일럿으로 정했고, 유형마다 하위라벨(분모/비교 기준, 지역/채널/하위 유형 등)을 분리해 저장한다
- **판정과 결합을 나눈다.** 이 시스템은 결합 키·정규화 필요 여부·미결합 예상까지 판정해 전달하고, 결합 실행과 지표 계산은 그 판정을 받는 쪽의 몫이다
- **유사도 판정은 9단계 등급.** 완전 동일 1.00부터 하위·유사 항목 0.50까지. 자동 확정 기준은 0.90 — 0.70~0.90 구간을 시험해 정확도 저하 없이 과탐만 줄어드는 값으로 정했다
- **매핑 근거는 3계층으로 기록.** 후보 목록 · 알고리즘 추천 · 최종 결정을 분리해 저장한다. 추천 목록에 없는 값을 결정하면 별도 표기한다
- **식별자는 무손실 보존.** 데이터셋의 60%만 자체 식별자를 갖고 그중 50%만 URI 형태라, 주 식별자 하나로는 동일 데이터셋을 판별할 수 없다. 수집 과정에서 붙은 식별자를 모두 보존해 병합 판정에 쓴다
- 유사 속성 탐지 성능: 공개 벤치마크 12종 기준 **F1 평균 0.87** (baseline 0.72 → 0.94까지 개선된 데이터셋도 있음)

**스택** — FastAPI · PostgreSQL(JSONB) · DCAT 3.0 · Apache Airflow · MinIO · XGBoost · Transformers · LangGraph · React

## 실행

```bash
npm install
npm run dev
```

이 데모는 React + TypeScript + Vite로 만들었고, 외부 런타임 의존성은 React뿐입니다.
관계 지도는 라이브러리 없이 SVG로 직접 그렸습니다 — 노드 위치를 각도와 단계 수로 계산해 **항상 같은 배치**가 나오도록 했습니다.
온보딩 투어도 투어 라이브러리 없이, 대상 요소에 큰 `box-shadow`를 줘서 주변만 어둡게 하는 방식으로 만들었습니다 (오버레이 DOM이 없어 하이라이트된 요소를 그대로 클릭할 수 있습니다).

```
src/
  App.tsx          화면 셸 — 헤더, 메뉴, 화면 전환
  Tour.tsx         온보딩 투어 7단계
  data.ts          목 데이터 — 관계 유형·그래프·수집 이력
  portal.css       화면 스타일 (라이트·다크 both)
  screens/         화면 5개
```
